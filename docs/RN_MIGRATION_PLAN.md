# Carlib → React Native + Expo Migration Plan

*Written August 2026. All versions, APIs, and issue numbers below were verified against live docs/npm/GitHub in August 2026 — not from memory.*

## 0. Verdict

**Yes — Liquid Glass in Expo is real and production-viable.** `expo-glass-effect` is an official Expo package (v57.0.1, versioned with SDK 57), and the bigger win is that Expo's *native chrome* — the `NativeTabs` tab bar, native stack headers, and form sheets — adopts Liquid Glass automatically on iOS 26 with zero code, while rendering Material 3 on Android. Apple is making Liquid Glass effectively mandatory in iOS 27 (the `UIDesignRequiresCompatibility` opt-out is being removed), and apps using *native* glass inherit the iOS 27 refinements without recompiling — so the strategy is **native chrome first, one `Glass` wrapper for custom surfaces, opaque-card fallback on Android**.

Approach: **rebuild, not transliterate.** The Swift app is a mock-data prototype (no backend), the design system is token-complete, and every screen is inventoried below — so this is a faithful re-implementation in idiomatic RN, keeping the exact tokens, copy, seed data, and flows.

Rough sizing: **1.5–3 dev-months** for one developer for a faithful two-platform port (~38 screens, mock data, design system spec in hand).

## 2. Liquid Glass strategy

Three layers, in order of preference:

1. **Free native chrome** (zero code, inherits iOS 27 improvements automatically):
   - `NativeTabs` → real `UITabBarController` → Liquid Glass tab bar on iOS 26, classic bar on iOS ≤18, **Material 3 bottom nav on Android**. Bonus: `minimizeBehavior="onScrollDown"`.
   - Native stack headers → glass automatically on iOS 26. Pattern: `headerTransparent: true`, and `headerBlurEffect: undefined` on iOS 26+ but `'regular'` on older iOS (an explicit blur on iOS 26 hides the large title).
   - `presentation: 'formSheet'` with `sheetAllowedDetents` → auto-glass sheets on iOS 26; ~direct analog of the app's 8 `presentationDetents` sheets.

2. **One custom `Glass` wrapper** for hand-built surfaces (the Shops drawer, frosted chips):

   ```tsx
   // src/components/Glass.tsx
   const canGlass =
     Platform.OS === 'ios' &&
     isGlassEffectAPIAvailable() &&
     isLiquidGlassAvailable();   // + respect AccessibilityInfo.isReduceTransparencyEnabled()

   // canGlass → <GlassView glassEffectStyle="regular" style={{ borderRadius: 24 }} />
   // else     → opaque themed card (tileSecondary fill, border, elevation on Android)
   ```

   **Android fallback = opaque brand cards** (the community consensus), not blur mimicry — keeps the Carlib identity and avoids expo-blur's Android <12 slow paths. Use expo-blur only where translucency is essential.

3. **@expo/ui SwiftUI `glassEffect()`** for exotic cases (glass morphing via `glassEffectId` in a `GlassEffectContainer`). Not needed for v1.

**Hard rules** (all from verified bug reports/docs):
- Never set `opacity: 0` on a `GlassView` or any parent — it silently kills the effect (expo#41024). Fade via `glassEffectStyle: {style, animate, animationDuration}` instead.
- Uniform `borderRadius` only — per-corner radii regressed (expo#40778).
- Never apply `glassEffect()` to a Menu label (halo artifact) — use `buttonStyle('glass')`.
- Glass on contained surfaces only (cards, bars, chips), never full screens; never gate critical actions behind a glass-only surface.
- Guard everything with `isGlassEffectAPIAvailable()` (iOS 26 beta crash, expo#40911).
- Watch expo#41025 (glass flicker during expo-router + NativeTabs transitions) — prototype the Shops drawer early.

**Root routing** is a pure function of `authStatus` exactly as in `RootView`: `unknown` → Splash; `unauthenticated`/`sessionExpired` → welcome; authenticated + no role → role-selection; else the role's tab group. Cross-fade transitions (~300ms) between root states.

**NativeTabs constraints** (validated against the app's needs):
- NativeTabs **at the navigation root** of each role group — never nested inside a Stack (iOS release-build icon corruption, expo#42364).
- Tab-bar hiding for the expanded Shops drawer: `hidden` prop on `NativeTabs` + a context + `useFocusEffect` (docs-sanctioned pattern; equivalent of `.toolbar(.hidden, for: .tabBar)`).
- `pendingDriverTab`/`pendingGarageTab` → keep the zustand-intent pattern; the tab layout consumes the intent with `router.navigate('/(driver)/(tabs)/home')` and nils it.
- Tab icons: Remixicon glyphs rasterized with `getImageSourceSync` → `Icon src` (works on both platforms), `renderingMode: 'template'`.
- Avoid FlatList directly under tab roots where scroll-to-top/minimize matters (documented NativeTabs limitation).

## 4. Design system port (token-for-token)

**Dark mode is a shipping feature.** (CLAUDE.md's "dark toggle disabled" note is stale — the Settings theme picker shipped 2026-04-21 and writes `app_theme`; all ~20 adaptive tokens have complete dark values.) The RN theme provider must support Light/Dark/System with **Light as the persisted default** (not System — matching `@AppStorage` fallback), plus two per-screen forces: Splash always dark, WelcomeCarousel always light.

- **Colors** — port the exact table from `CarlibColors.swift` (light+dark pairs: screenBg `#FFFFFF/#0F0F0F`, tileSecondary `#F1F1F4/#1E1E1E`, brandYellow `#F5B700`, the 9 status fg colors + adaptive bgs, etc.). Rename the misleading `*Blue` tokens to `brandYellow*`. Skip the dead asset-catalog tokens (`CarlibPrimary`, `CarlibSuccess`… reference colorsets that don't exist).
- **Typography** — Aeonik scale: largeTitle 28 / title1 26 / title2 22 / title3 17 / body 15 / callout 14 / footnote 13 / caption 13, titles default **medium**; off-scale styles (heroNumber 48 bold, splashHero 42, amount 36…). Map legacy aliases. Set explicit `lineHeight` ≈ 1.25× (SwiftUI computed these implicitly) and visually QA. `sectionHeaderStyle` = 13 medium, `letterSpacing: 0.8`, uppercase, carlibLabel. No semibold file — semibold maps to Bold.
- **Spacing/Radius** — 4/8/12/16/20/24/32/40/48; minTouchTarget 48; radius 4/8/12/16/24/9999.
- **Components** (specs verified from source):
  - `CarlibButton`: 52pt capsule, 4 variants; **primary flips** black-on-white ↔ white-on-black by theme; disabled = 0.5 opacity; loading = fg-tinted spinner.
  - `CarlibTextField`/`SecureField`: 52pt, radius 12, tileSecondary fill, **no border, no focus styling**; error = red caption below only; eye toggle on secure.
  - `CarlibCard` (radius 16, padding 16, optional 1pt border — **no shadows anywhere in the DS**; suppress Android ripple/elevation defaults).
  - `CarlibStatusBadge`: three TS `Record<Status, {fg, bg, icon}>` maps (Claim 9 / Booking 7 / Repair 5) — full mapping in the design-system audit.
  - `PolestarTile` (180pt, 34pt corner icon at 0.2/0.4 opacity), `CarlibSectionHeader`, `CarBrandLogo` (18 brand PNGs + alias spellings, fallback `car-line`), `DummyImage` (expo-image over the same Unsplash/pravatar URL pools — **use FNV-1a hashing**; Swift's `hashValue` is launch-random, so the iOS "determinism" was actually a bug).
  - `PressableScale`: Reanimated `withSpring(pressed ? 0.96 : 1)` (0.97 tiles) tuned to SwiftUI's `response: 0.28, dampingFraction: 0.72`, haptic on press-in only (`Soft`/`Light`; Android `performAndroidHapticsAsync`).
- **Icons**: script parses the 3,229-case `RemixIcon.swift` enum → `glyphmap.json` → `createIconSet(glyphMap, 'remixicon', 'remixicon.ttf')`. Port the ~75 semantic aliases from `LucideIcon.swift` as a TS const map. (One stray SF Symbol `chevron.left` in GarageSearchView → `arrow-left-s-line`.)
- **Theme-dependent assets**: `HomeTopBg` light PNG / dark SVG swap must be manual (`useColorScheme` conditional source). `FindShopMap` dark treatment used `.colorInvert()` — ship a pre-inverted PNG instead. PhotoLightbox stays always-black.

## 5. Data, state, and auth

- **Models** (`src/models`): TS interfaces for User, Claim, PhotoAttachment, VehicleInfo, Vehicle, Garage, Booking, TimeSlot, CountryDialCode (14 entries, FR default). **Enum raw values are French strings** (`'pris_en_charge'`, `'conducteur'`…) — keep them as the union literals so persisted data stays compatible. Port `stageIndex` (9 ClaimStatus states → 5 hero stages).
- **`useAppStore`** (zustand): `authStatus`, `currentUser`, `pendingDriverTab`, `pendingGarageTab`; `completeAuth`, `signOut` (clears SecureStore), `setUserRole` (also persists user to SecureStore — matches the Swift computed setter).
- **`useClaimStore`** (zustand, in-memory, seeded from mock data): replicate the exact filter predicates (`activeClaims`, `pastClaims`, `availableClaims`, `garageClaims`) and the **side-effect couplings**: `acceptClaim` sets `status/assignedGarageId/bookingStatus:'pending'` *on the claim* (no Booking record); `addBooking` appends a Booking *and* marks the slot unavailable; `updateRepairStatus('readyForPickup')` forces claim `completed`, any other repair status forces `repairing`; vehicle default promotion rules; `addClaim` unshifts (newest first).
- **MockData**: port verbatim — fixed UUIDs (`00000001…` garages, `10000001…` claims, `20000001…` vehicles), 6 Paris garages, 17 claims covering every status, `garageDistances`/`garageYearsActive` maps, and time slots **regenerated relative to today's startOfDay** on each launch.
- **Auth**: port the mock service 1:1 — 4 `DefaultUsers` seeds (all password `password`, see `TEST_ACCOUNTS.md`), 1s fake latency, ≥8-char sign-up validation, SecureStore keys `session_token` + `current_user`. Apple sign-in via `expo-apple-authentication` (`isAvailableAsync()` gate; note the Swift entitlements file was actually *empty* — the RN app will be the first to wire the capability properly, and EAS handles the entitlement via `ios.usesAppleSignIn`). **Product flags, not silent ports**: (a) returning sign-up users are accepted with *any* password (password never stored) — reproduce for parity but flag; (b) forgot-password / change-password / driver-profile-edit Save are visual no-ops; (c) bookings are not linked to claims.
- **Claim photos**: store **file URIs** from expo-image-picker on the claim (RN-idiomatic), not base64 blobs — 8 in-memory images is the one place a 1:1 data port would be wrong.

## 6. i18n

The app is **already fully bilingual EN+FR** (~394 keys ≈ 788 strings via the `tr(en, fr)` helper — CLAUDE.md's "copy is English" is stale; the FR copy is deliberate, idiomatic insurance French). Port:

- `L10n.Namespace.key` → nested i18next keys (`t('driverHome.greeting', {name})`), `en.json` + `fr.json`, **preserving the existing FR translations verbatim** (don't re-translate).
- The 16 parameterized functions → interpolation; the hand-rolled plural branches (`repairBody` days/jours, `shortcutMyGarageCars`) → i18next plural rules; keep locale quirks (`À %.1f km` vs `%.1f km away`, `N°%02d`) and embedded `\n` line breaks (layouts depend on them).
- TS key-safety via i18next `CustomTypeOptions` declaration merging (replaces the Swift enum's compile-time checking).
- Language picker writes `app_language`; changing language re-renders via i18next (no need for the Swift full-tree remount hack). Dates stay pinned `en_US` (date-fns `enUS`) to match current behavior.
- `Localizable.xcstrings` is vestigial auto-extraction shrapnel — ignore it.

## 8. Phased build plan

**Phase 0 — Foundation (≈ week 1)**
Scaffold (`--template default@sdk-57`), dev builds running on iOS device/simulator + Android, EAS project, fonts embedded, Remixicon glyph-map codegen + `<RemixIcon>` component, full `theme/` port, ThemeProvider (System/Dark/Light, light default), `PressableScale`, `Glass` wrapper, `CarlibButton`/`TextField`/`Card`/`Badge`/`SectionHeader`/`PolestarTile`.

Models + enums, both zustand stores, MockData port, mock AuthService + SecureStore session, root auth gate with cross-fades, Splash (staged wordmark animation, always-dark), **WelcomeCarousel** (stories mechanics hand-built: 4s auto-advance timer, tap-left/right zones, long-press-pause ≥0.2s, segmented progress bars — Reanimated, no pager needed), SignIn/SignUp/Forgot as formSheets, RoleSelection, Apple sign-in button (iOS, `isAvailableAsync` gated).

**Phase 3 — Shops map + booking (≈ week 5; the hardest screen — prototype the drawer in Phase 0 spare time)**

## 9. Risks & decisions register

| # | Risk / decision | Position |
|---|---|---|
| 1 | **NativeTabs is alpha** | Accept. The JS-Tabs fallback inherits an *open* iOS release-build boot-hang with per-tab stacks (expo#47687 / RN#57511) — worse than alpha. Keep NativeTabs at root; test Release builds from week 1. |
| 2 | **Shops drawer can't overlap native tab bar** | Design adaptation (documented in §8 Phase 3): float above the bar; discrete bar-hide on expand (same limitation SwiftUI has). If product demands literal overlap → custom JS bottom chrome for that role, losing free glass. |
| 3 | **Glass flicker on transitions** (expo#41025) | Prototype drawer + tab transitions on a real iOS 26 device in Phase 0/3 before committing. |
| 4 | **Aeonik is a commercial CoType Foundry font** | ⚠️ Verify the license covers Android/RN embedding *before* the Android build ships. Blocker-class if not. |
| 5 | **Apple sign-in has no Android path** | Ship email/password (mock) on Android v1; add Google Sign-In later. Note Apple *requires* SIWA on iOS if any third-party login ships. |
| 6 | Android native-control divergences | Accepted: max 3 sheet detents, no headers inside form sheets, modal (not inline) time pickers, no context-menu previews, Material bottom nav instead of glass. All degrade to standard Android patterns. |
| 7 | Unsplash/pravatar hotlinking + trademarked car-brand logos | Fine for the prototype; flag before store submission. |
| 8 | Intentional-quirk ports (any-password fallback, no-op saves, unlinked bookings, `hasSeenWelcome` unused) | Replicate for parity; each flagged for product review rather than silently "fixed". |
| 9 | In-memory store = data lost on restart | By design (prototype). Do **not** add persistence silently — it changes product behavior. |
| 10 | Stale CLAUDE.md | Two claims are wrong: dark mode *is* user-reachable, and copy is *bilingual EN+FR*, not English-only. Update CLAUDE.md when the migration starts. |
